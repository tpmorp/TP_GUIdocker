# TP_GUIdocker 再設計書（第2版）

2026-10-06 作成。0.1.x の実機不具合と、4回の診断で確定した本体仕様に基づく。

---

## 1. 0.1.x の失敗の総括

| 現象 | 原因（確定） |
|---|---|
| 起動時・終了時に「レイアウトの読み込みに失敗しました」 | 自由分割用レイアウトで、**メディアエクスプローラーを切り離し状態にしていた**。本体はエクスプローラーの切り離しに対応しておらず、読み込みが失敗し、他パネルの適用まで崩れる |
| パネルが右上の区画に溜まる | 上記の失敗でパネルの照合（どの窓がどのパネルか）ができず、全パネルが既定の区画へ入った。加えて、型に無いパネルを1つの区画へ集める設計そのものにも問題があった |
| 新しく開いたパネルも右上へ入る | 同上 |
| 本体の設定が「全パネルが浮いた状態」で保存された | 終了時の戻し（戻り先レイアウトの適用）も同じ原因で失敗した |

**教訓**：本体の仕様を推測で扱ったこと。今後は、本体へ渡すものはすべて実験で確かめた形に限り、適用の結果も必ず検証する。

## 2. 実験で確定した本体の仕様

| # | 仕様 | 根拠 |
|---|---|---|
| S1 | 本体標準パネル・他者製パネルとも、切り離すと独立窓（`aviutl2Manager`）になり、子窓化して取り込める | 段階0 |
| S2 | レイアウトファイルは**適用した瞬間に読まれる**（起動時の内容を使い回さない） | 0.1.1 のログ |
| S3 | レイアウトの一覧（メニュー）は本体の起動時に作られる。新しいファイルは再起動まで一覧に出ない | 段階0 |
| S4 | `floating=1` と `x,y,w,h` を指定すると、その位置・大きさで切り離される（誤差0） | 診断2・3 |
| S5 | 非表示パネル（本体標準・他者製）も切り離し状態にできる。後から表示すると、指定位置に浮いた窓で現れる | 診断3・4 |
| S6 | **メディアエクスプローラーは切り離し不可**。レイアウトで指定すると読み込み失敗（表示中・非表示、番号を問わない）。右クリックにも切り離し項目が無い | 診断3・4、利用者の確認 |
| S7 | 読み込みに失敗すると、エラー表示が複数回出て、他のパネルの適用も崩れる。直後の別レイアウトの適用でもエラーが出る（本体内部の状態が乱れる） | 診断1・3・4 |
| S8 | 「レイアウトを作成」画面は、名前の入力欄・「メインウィンドウの位置も保存する」・OK で構成され、自動操作できる | 部品構成の読み取り |
| S9 | 右クリックメニューは `TrackPopupMenu` で表示され、横取りできる。項目番号は毎回変わるため文字列で判定する | 段階0 |
| S10 | `aviutl2.ini` には、削除済みプラグインの古いセクションや、レイアウトに無い項目（`DisplayZoom` 等）が混ざる | 0.1.0 |

## 3. 再設計の方針

### 3.1 本体レイアウトの扱い（根本の変更）

**旧**：`aviutl2.ini` を読んで戻り先と自由分割用のレイアウトを自作する。ファイルを新規作成するため、初回は再起動が必要。

**新**：**本体自身に「レイアウトを作成」させる**（S8）。
1. 自由分割に入る直前、プラグインが「レイアウトを作成」を自動操作する。名前は `TP_GUIdocker_元の配置` とし、本体に**今この瞬間の配置**を保存させる。
   - 本体が書くため、形式・セクションは常に正しい（S10 の問題が消える）
   - 終了時の時点ではなく、直前の配置を保存できる
2. 自由分割用の `TP_GUIdocker` が一覧に無ければ、同じく「レイアウトを作成」で枠だけ作らせる（本体がメニューに登録する）。
3. その中身をプラグインが書き換えてから適用する（S2 により、書き換えた内容が使われる）。
   - **初回の再起動が不要になる**（S3 の制約を回避）
4. 自由分割用レイアウトの中身は、`TP_GUIdocker_元の配置`（本体が今書いたもの）を土台にする。
   - エクスプローラーには**一切触れない**（S6）
   - その他のパネルは表示・非表示を問わず切り離し、照合用の一意の位置を与える（S4・S5）
5. 戻すときは `TP_GUIdocker_元の配置` を適用する（本体が書いたものなので失敗しない）。

### 3.2 適用結果の検証（安全装置の強化）

- レイアウトの適用中は本体のエラー表示を監視する（診断で実装済みの仕組みを本番へ）。
- エラーが出た場合、または表示すべきパネルが指定位置に現れない場合は、次のように処理する。
  - 直ちに自由分割を中止して元の配置へ戻す
  - 理由を利用者に知らせる
  - 記録に残す
- 自動で閉じるのは「レイアウト」に関するエラー表示だけとし、他の表示には触れない。

### 3.3 パネルの照合

- 一意の位置による照合（S4 で誤差0を確認済み）を正とする。
- 題名は表示用にのみ使う。エクスプローラーの題名は開いているフォルダ名に変わるため、識別には使わない。

### 3.4 初期配置と、パネルの出し入れ

- **初期配置**：本体標準パネルだけの AE 風の最小構成。
  ```
  ┌──────────┬────────────────┬──────────────┐
  │シーン     │ プレビュー編集 │ オブジェクト │
  │リスト     │                │ 設定         │
  ├──────────┴────────────────┴──────────────┤
  │ レイヤー編集                               │
  └────────────────────────────────────────────┘
  ```
  - 他者製パネルは、初めて自由分割に入るときは非表示にする（元の配置に戻せば、元どおり表示される）。
- **パネルを開く**：自由分割中に「表示」メニューで開いたパネルは、**浮いた窓のまま**出す（自動で取り込まない）。
  - 位置は、照合用の仮位置から、メイン窓の中央付近へ移す。
  - 利用者がドラッグで区画へ入れる（段階2）。
- **パネルを閉じる**：区画内のパネルを本体の「ウィンドウを閉じる」で閉じると、そのタブが消える。区画が空になったら、区画ごと閉じて隣の区画が広がる（段階2）。
- **浮いた窓の記憶**：自由分割中に浮いたままのパネルは、位置と大きさを記憶し、次回も浮いた窓で復元する。

### 3.5 メディアエクスプローラーの扱い（要相談）

本体の仕様で切り離せないため（S6）、自由分割の区画へは入れられない。案は次の3つ。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 本体の領域を残す | 分割画面の一部に「本体の領域」を設ける。エクスプローラーは本体が従来どおりそこへ描く。領域の位置・大きさは分割画面に合わせ、レイアウトで本体へ指示する | エクスプローラーを自由分割中も使える | 領域の大きさを変えるたびに本体へレイアウトを適用し直す必要がある。実現性の追加検証が必要 |
| B. 自由分割中は使わない | エクスプローラーは標準画面でのみ使う | 単純・確実 | 自由分割中に素材を探せない |
| C. 一時的に標準画面へ | エクスプローラーを開くと一時的に標準画面へ戻り、閉じると自由分割へ戻る | 実装は比較的単純 | 切り替えのたびに画面が組み替わる |

### 3.6 本体の終了と次回起動

- 本体の終了時は、まず元の配置へ戻し、本体にその状態で設定を保存させる。プラグインを外しても標準画面で起動できる状態を保つためである（0.1.x と同じ）。
- 次回起動時、前回が自由分割なら自動で自由分割に入る。
- 異常終了を検知した場合（自由分割中の印が残っている場合）は、まず `TP_GUIdocker_元の配置` を適用して本体の状態を正常に戻し、それから自由分割に入る。

### 3.7 変えないもの

以下は 0.1.x の実装を引き継ぐ。いずれも実機で動作を確認済み。
- 分割木
- 境界線ドラッグ
- タブ
- 入れ物の配置（メニューバーとフッターの間）
- パネルの勝手な移動・サイズ変更の阻止
- 「ウィンドウを統合」の阻止
- 設定の専用ファイルへの保存

## 4. 処理の流れ（新）

### 自由分割に入る
1. 本体の更新確認（バージョンが変わっていれば利用者に確認）
2. 「レイアウトを作成」を自動操作し、`TP_GUIdocker_元の配置` を本体に保存させる（同名があれば上書き）
3. `TP_GUIdocker` が一覧に無ければ、同じ方法で作らせる
4. `TP_GUIdocker_元の配置` を土台に、自由分割用の中身を生成して `TP_GUIdocker.layout` を書き換える
5. エラー表示を監視しながら `TP_GUIdocker` を適用する
6. 検証
   - エラー表示が無いこと
   - 分割木に属する表示パネルが、すべて指定位置に現れたこと
   - 満たさなければ、元の配置へ戻して中止する
7. 分割木に属するパネルを取り込み、入れ物をメイン窓に置く
8. 浮いた窓として記憶しているパネルを、記憶した位置へ移す

### 自由分割を抜ける
1. 全パネルを返却（子窓化を解除）
2. エラー表示を監視しながら `TP_GUIdocker_元の配置` を適用する

## 6. 試験の方針

- 単体試験：分割木・レイアウトファイルの読み書き・自由分割用レイアウトの生成（エクスプローラーに触れないこと、全パネルに一意の位置が付くこと）
- 実機試験：段階ごとに番号付きの手順で確認していただく。記録ファイルで本体のエラー表示の有無と照合結果を確認する
- 診断機能は開発中は残し、公開前に外す
