# TP_GUIdocker 再設計書（第2版）

2026-10-06 作成。0.1.x の実機不具合と、4回の診断で確定した本体仕様に基づく。

---

**用語（2026-10-06 決定）**：利用者に見せる表記では「自由分割」という語を使わない。機能の開始・終了は「TP_GUIdocker を有効化」「TP_GUIdocker を無効化」と表す。本書中の「自由分割」は内部の説明用語である。

## 1. 0.1.x の失敗の総括

| 現象 | 原因（確定） |
|---|---|
| 起動時・終了時に「レイアウトの読み込みに失敗しました」 | 自由分割用レイアウトで、**メディアエクスプローラーを切り離し状態にしていた**。本体はエクスプローラーの切り離しに対応しておらず、読み込みが失敗し、他パネルの適用まで崩れる |
| パネルが右上の区画に溜まる | 上記の失敗でパネルの照合（どの窓がどのパネルか）ができず、全パネルが既定の区画へ入った。加えて、型に無いパネルを1つの区画へ集める設計そのものにも問題があった |
| 新しく開いたパネルも右上へ入る | 同上 |
| 本体の設定が「全パネルが浮いた状態」で保存された | 終了時の戻し（戻り先レイアウトの適用）も同じ原因で失敗した |

**教訓**：本体の仕様を推測で扱ったこと。今後は、本体へ渡すものはすべて実験で確かめた形に限り、適用の結果も必ず検証する。

## 2. 実験で確定した本体の仕様

| # | 仕様 | 根拠 |
|---|---|---|
| S1 | 本体標準パネル・他者製パネルとも、切り離すと独立窓（`aviutl2Manager`）になり、子窓化して取り込める | 段階0 |
| S2 | レイアウトファイルは**適用した瞬間に読まれる**（起動時の内容を使い回さない） | 0.1.1 のログ |
| S3 | レイアウトの一覧（メニュー）は本体の起動時に作られる。新しいファイルは再起動まで一覧に出ない | 段階0 |
| S4 | `floating=1` と `x,y,w,h` を指定すると、その位置・大きさで切り離される（誤差0） | 診断2・3 |
| S5 | 非表示パネル（本体標準・他者製）も切り離し状態にできる。後から表示すると、指定位置に浮いた窓で現れる | 診断3・4 |
| S6 | **メディアエクスプローラーは切り離し不可**。レイアウトで指定すると読み込み失敗（表示中・非表示、番号を問わない）。右クリックにも切り離し項目が無い | 診断3・4、利用者の確認 |
| S7 | 読み込みに失敗すると、エラー表示が複数回出て、他のパネルの適用も崩れる。直後の別レイアウトの適用でもエラーが出る（本体内部の状態が乱れる） | 診断1・3・4 |
| S8 | 「レイアウトを作成」画面は、名前の入力欄・「メインウィンドウの位置も保存する」・OK で構成され、自動操作できる | 部品構成の読み取り |
| S9 | 右クリックメニューは `TrackPopupMenu` で表示され、横取りできる。項目番号は毎回変わるため文字列で判定する | 段階0 |
| S10 | `aviutl2.ini` には、削除済みプラグインの古いセクションや、レイアウトに無い項目（`DisplayZoom` 等）が混ざる | 0.1.0 |

## 3. 再設計の方針

### 3.1 本体レイアウトの扱い（根本の変更）

**旧**：`aviutl2.ini` を読んで戻り先と自由分割用のレイアウトを自作する。ファイルを新規作成するため、初回は再起動が必要。

**新**：**本体自身に「レイアウトを作成」させる**（S8）。
1. 自由分割に入る直前、プラグインが「レイアウトを作成」を自動操作する。名前は `TP_GUIdocker_元の配置` とし、本体に**今この瞬間の配置**を保存させる。
   - 本体が書くため、形式・セクションは常に正しい（S10 の問題が消える）
   - 終了時の時点ではなく、直前の配置を保存できる
2. 自由分割用の `TP_GUIdocker` が一覧に無ければ、同じく「レイアウトを作成」で枠だけ作らせる（本体がメニューに登録する）。
3. その中身をプラグインが書き換えてから適用する（S2 により、書き換えた内容が使われる）。
   - **初回の再起動が不要になる**（S3 の制約を回避）
4. 自由分割用レイアウトの中身は、`TP_GUIdocker_元の配置`（本体が今書いたもの）を土台にする。
   - エクスプローラーには**一切触れない**（S6）
   - その他のパネルは表示・非表示を問わず切り離し、照合用の一意の位置を与える（S4・S5）
5. 戻すときは `TP_GUIdocker_元の配置` を適用する（本体が書いたものなので失敗しない）。

### 3.2 適用結果の検証（安全装置の強化）

- レイアウトの適用中は本体のエラー表示を監視する（診断で実装済みの仕組みを本番へ）。
- エラーが出た場合、または表示すべきパネルが指定位置に現れない場合は、次のように処理する。
  - 直ちに自由分割を中止して元の配置へ戻す
  - 理由を利用者に知らせる
  - 記録に残す
- 自動で閉じるのは「レイアウト」に関するエラー表示だけとし、他の表示には触れない。

### 3.3 パネルの照合

- 一意の位置による照合（S4 で誤差0を確認済み）を正とする。
- 題名は表示用にのみ使う。エクスプローラーの題名は開いているフォルダ名に変わるため、識別には使わない。

### 3.4 初期配置と、パネルの出し入れ

- **初期配置**：本体標準パネルだけの AE 風の最小構成。
  ```
  ┌──────────┬────────────────┬──────────────┐
  │シーン     │ プレビュー編集 │ オブジェクト │
  │リスト     │                │ 設定         │
  ├──────────┴────────────────┴──────────────┤
  │ レイヤー編集                               │
  └────────────────────────────────────────────┘
  ```
  - 他者製パネルは、初めて自由分割に入るときは非表示にする（元の配置に戻せば、元どおり表示される）。
- **パネルを開く**：自由分割中に「表示」メニューで開いたパネルは、**浮いた窓のまま**出す（自動で取り込まない）。
  - 位置は、照合用の仮位置から、メイン窓の中央付近へ移す。
  - 利用者がドラッグで区画へ入れる（段階2）。
- **パネルを閉じる**：区画内のパネルを本体の「ウィンドウを閉じる」で閉じると、そのタブが消える。区画が空になったら、区画ごと閉じて隣の区画が広がる（段階2）。
- **浮いた窓の記憶**：自由分割中に浮いたままのパネルは、位置と大きさを記憶し、次回も浮いた窓で復元する。

### 3.5 メディアエクスプローラーの扱い（要相談）

本体の仕様で切り離せないため（S6）、自由分割の区画へは入れられない。案は次の3つ。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 本体の領域を残す | 分割画面の一部に「本体の領域」を設ける。エクスプローラーは本体が従来どおりそこへ描く。領域の位置・大きさは分割画面に合わせ、レイアウトで本体へ指示する | エクスプローラーを自由分割中も使える | 領域の大きさを変えるたびに本体へレイアウトを適用し直す必要がある。実現性の追加検証が必要 |
| B. 自由分割中は使わない | エクスプローラーは標準画面でのみ使う | 単純・確実 | 自由分割中に素材を探せない |
| C. 一時的に標準画面へ | エクスプローラーを開くと一時的に標準画面へ戻り、閉じると自由分割へ戻る | 実装は比較的単純 | 切り替えのたびに画面が組み替わる |

**決定（2026-10-06）**：段階4で改めて検討する。それまでは案 B の扱いとする。
- 自由分割中はエクスプローラーを非表示にする。
- 「表示」メニューから開こうとした場合は、自由分割中は使えない旨を知らせる。

### 3.6 本体の終了と次回起動

- 本体の終了時は、まず元の配置へ戻し、本体にその状態で設定を保存させる。プラグインを外しても標準画面で起動できる状態を保つためである（0.1.x と同じ）。
- 次回起動時、前回が自由分割なら自動で自由分割に入る。
- 異常終了を検知した場合（自由分割中の印が残っている場合）は、まず `TP_GUIdocker_元の配置` を適用して本体の状態を正常に戻し、それから自由分割に入る。

### 3.7 変えないもの

以下は 0.1.x の実装を引き継ぐ。いずれも実機で動作を確認済み。
- 分割木
- 境界線ドラッグ
- タブ
- 入れ物の配置（メニューバーとフッターの間）
- パネルの勝手な移動・サイズ変更の阻止
- 「ウィンドウを統合」の阻止
- 設定の専用ファイルへの保存

## 4. 処理の流れ（新）

### 自由分割に入る
1. 本体の更新確認（バージョンが変わっていれば利用者に確認）
2. 「レイアウトを作成」を自動操作し、`TP_GUIdocker_元の配置` を本体に保存させる（同名があれば上書き）
3. `TP_GUIdocker` が一覧に無ければ、同じ方法で作らせる
4. `TP_GUIdocker_元の配置` を土台に、自由分割用の中身を生成して `TP_GUIdocker.layout` を書き換える
5. エラー表示を監視しながら `TP_GUIdocker` を適用する
6. 検証
   - エラー表示が無いこと
   - 分割木に属する表示パネルが、すべて指定位置に現れたこと
   - 満たさなければ、元の配置へ戻して中止する
7. 分割木に属するパネルを取り込み、入れ物をメイン窓に置く
8. 浮いた窓として記憶しているパネルを、記憶した位置へ移す

### 自由分割を抜ける
1. 全パネルを返却（子窓化を解除）
2. エラー表示を監視しながら `TP_GUIdocker_元の配置` を適用する

## 7. 実施記録

- 2026-10-06 段階1' 完了（version 0.2.4）。実機で確認済みの事項は次のとおり。
  - 有効化時にエラー・警告音が出ない
  - AE 風最小構成で4枚が区画に入る
  - 境界線ドラッグで大きさを変えられ、再起動後も保たれる
  - 「表示」から開いたパネルは浮いた窓で中央に出て、位置は次回も復元される
  - メディアエクスプローラーは案内を出して開かせない
  - 起動時は「有効化しています…」の覆いで通常の画面を見せない
  - 無効化でエラー無しに元の配置へ戻る
  - メニューは「TP_GUIdocker を有効化／無効化」の1項目で切り替わる
- 2026-10-07 配布版でパッケージ（au2pkg.zip）をプレビューへドロップすると本体が落ちた。Windows の記録では落ちた箇所は他者製プラグイン（HL_FxWheel、それを外すと PaletteHistory）の「取り外し済み」の処理。本体はパッケージ導入時に全プラグインを取り外して読み込み直し、後片付けをしないプラグインが落ちると判断。説明書きは「手で置く導入」を先に案内し、TP_GUIdocker は解放時の後片付けを強化（version 0.4.8）。
- 2026-10-11 友人の常用環境（本体 2.1.13、プラグイン多数）で有効化が「『レイアウトを作成』がメニューに無い」で中止。最小環境では動く。同じ環境でメニューの小分け（全体を再帰的に探す）は成功しており、他のプラグインが「表示」メニューの文字か構成を変えていると推定。メニュー探索を `menu_find.cpp` に分け、文字のそろえ（アクセスキー・「...」等）と、決め打ちの道筋で無い時の目印（「レイアウトを作成」を持つ下位メニュー、その親を「表示」とみなす）による探索を追加。見つからない時はメニュー構成を記録に書き出す（version 0.4.9）。
- 2026-10-12〜17 0.4.9 の診断記録で、有効化に失敗した時は本体のメニュー（ファイル・編集・表示・その他）の中身が空で、メニューバーに更新の知らせ「更新」が出ていたと判明。利用者がメニューを一度開くと中身ができ、その後の有効化は成功する。0.4.10 でメニューを開いた時の知らせ（WM_INITMENUPOPUP）を人工的に送って中身を作らせたところ、その直後に本体が落ちた記録が3回（例外 0xc0000005、本体内）。この知らせは送ってはならない。0.4.12 で取り除き、起動時の有効化はメニューの中身ができるまで約3秒待ち、できなければ知らせを出さずに見送る（利用者がメニューから有効化できる）。本体の小さな更新（2.1.x の範囲）では確認を出さない（0.4.11）。

## 8. 段階2 ドッキングの仕様（2026-10-06 決定・version 0.3.0 で実装）

| 項目 | 仕様 |
|---|---|
| ドラッグの開始 | タブを長押し（`LONG_PRESS_MS`、既定 0.3 秒）してから動かす。長押しの前に動かした場合はドラッグにしない（誤って外れる対策）。長押しが成立すると、カーソルが移動の形になり、タブの影が出る |
| 落とし先の見せ方 | 「十字ボタン式」と「区画の領域式」の両方を実装。メニュー「落とし先の表示を切り替え」で使い比べられる。どちらの方式でも、タブ帯の上に落とすとタブとして重ね、差し込む位置はカーソルで決まる |
| 予告表示 | 置かれる範囲を半透明の色（`DROP_HIGHLIGHT`・`DROP_ALPHA`）で塗る |
| 入れ物の外で放す | 浮いた窓にする（`DROP_OUTSIDE`） |
| 浮いた窓を入れる | 浮いた窓をタイトル部分でドラッグして区画の上へ運ぶと、同じ落とし先の表示が出る。放すとその区画へ入る（Esc で取り消した移動では入れない） |
| 取り消し | ドラッグ中に Esc キー |
| 右クリック（タブ） | 浮かせる／閉じる／他の区画へ移動 ▸ 区画一覧／この区画を分割 ▸ 上下左右 |
| 右クリック（空き区画・タブ帯の空き） | この区画を分割 ▸ 上下左右／この区画を閉じる（空き区画のみ） |
| 空いた区画 | 自動で閉じ、隣が広がる。「この区画を分割」で作った空き区画は、パネルが入るか「この区画を閉じる」まで残る |
| パネルを閉じた時 | 区画から外す。再び「表示」から開くと、浮いた窓で中央に出る |
| 文言・見た目・動作の値 | すべて `docs/ui_spec.json`（指示書 `docs/TP_GUIdocker_指示書.xlsx`）で管理する |

- 2026-10-06 段階2 完了（version 0.3.2）。タブの長押しドラッグ、2方式の配置ガイド、浮いた窓の取り込み、右クリックの組み替えを実機で確認済み。

## 9. 段階3 ワークスペース・最大化・ロックの仕様（2026-10-06 決定・version 0.4.0 で実装）

| 項目 | 仕様 |
|---|---|
| ワークスペースの帯 | 入れ物の上端に細い帯（タブ帯と同じ高さ）。ワークスペース名のボタン、「＋」、右端にロックの表示を並べる |
| 保存した配置と使用中の配置 | 各ワークスペースは両方を持つ。操作で変わるのは使用中の配置だけで、保存した配置は「今の配置で上書き保存」した時だけ変わる（AE の「勝手に崩れる」不満への対策）。いつでも「保存時の配置に戻す」で戻せる |
| 切り替え | ボタンのクリック、または「TP_GUIdocker」→「ワークスペース」→「ワークスペース1〜9に切り替え」。後者は本体の「ショートカットキーの設定」でキーを割り当てられる。切り替えは本体のレイアウト機能で全パネルを切り離し直して行う（有効化と同じ確実な経路） |
| 右クリック（ボタン） | 名前を変更／今の配置で上書き保存（使用中のもののみ）／保存時の配置に戻す／削除（最後の1つは削除不可） |
| 「＋」 | 今の配置を元に、新しいワークスペースを名前を付けて作る |
| 最大化 | タブの右クリック「最大化」「元の大きさに戻す」、または「TP_GUIdocker」→「パネルを最大化・元に戻す」（ショートカットキー割り当て用。カーソルの下のパネルが対象）。最大化中は境界線を動かさない |
| ロック | 「TP_GUIdocker」→「レイアウトをロック」（1項目で切り替え、文字は状態を示す）、または帯の右端の「ロック」をクリック。ロック中はタブのドラッグと右クリックの組み替え（分離・閉じる・移動・分割・区画を閉じる）を禁止。境界線のドラッグと浮いた窓の取り込みは禁止しない（利用者の指定） |

- 2026-10-06 段階3 完了（version 0.4.4）。ワークスペースの帯と切り替え、保存した配置と使用中の配置、最大化、ロック、指示書による調整（帯の文字をメニューバーと同じ文字に、テーマの色）を実機で確認済み。「編集→プラグイン→TP_GUIdocker」の小分け（ワークスペース▸／表示の設定▸／配置の設定▸／指示用▸）も確認済み。
