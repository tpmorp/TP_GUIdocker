# AviUtl2 自由レイアウトプラグイン — 作成計画

## 背景
AviUtl2（導入済み 2.1.12、データフォルダ `C:\ProgramData\aviutl2`）の標準画面は、固定5区画にパネルを置く仕組み。区画の数・分け方は変えられない。
After Effects 同等以上に自由な画面構成を実現したい。

調査の結果、条件を満たすプラグインは存在しない。
- 旧AviUtl向けには、SplitWindow・アルティメットプラグイン「ワークスペース化」・AviUtlDock・UniteWindow がある。いずれも AviUtl2 非対応。
- AviUtl2 向けには該当品なし。導入済みの al2_* 群は見た目の調整のみ。

よって自作する（C++）。

## 方式（決定済み）
本体の各パネルを固定区画から取り外し、プラグインが用意する自由分割画面へ移し替える方式。
加えて、異常検知時は自動で本体標準の画面へ戻す「安全装置」を必須機能とする。

- 公式の手段は、自作パネルを本体へ組み込む `register_window_client` のみ。
- 本体パネルの取り外し・付け替えは、Windows の窓操作（親ウィンドウ変更・メッセージ横取り）で行う。

## 機能仕様草案
After Effects で多い不満への対策を含む。

1. **自由分割**
   - 縦横に何段でも分割可能。
   - 境界線はドラッグで調整。
   - 各パネルに最小サイズ、固定幅を指定可能。
2. **ドッキング**
   - パネルのタブをつかんで移動すると、落とし先（上下左右・タブとして重ねる）を大きく明示表示する。
   - 対策：AE の「落とし先が小さく分かりにくい」不満。
3. **メニューからの再ドッキング**
   - 右クリックメニュー「〜の隣へ移動」「元の位置へ戻す」。
   - 対策：AE はドラッグ以外で戻せない。
4. **ワークスペース**
   - 名前を付けて保存、ショートカットで切り替え、保存時の状態へリセット。
   - 明示的に保存するまで配置は一切変化しない。
   - 対策：AE の「勝手に配置が崩れる」不満。
5. **レイアウトロック**
   - 誤操作によるパネル移動・取り外しを防ぐ。
   - 対策：AE で要望の多い機能。
6. **パネル最大化**
   - AE の ` キー相当。1枚を一時的に全面表示する。
7. **表示の細部調整**
   - タブの高さ、余白、境界線の太さ、見出しの非表示、配色。
   - 導入済みのダーク化系と共存させる。
8. **独立ウィンドウ化**
   - パネルを別ウィンドウとして切り離す。マルチモニタに対応。
9. **安全装置**
   - 本体のバージョンが未検証の場合や、パネル取得に失敗した場合は、機能を停止して標準画面のまま起動する。
   - 本体の `aviutl2.ini` は書き換えず、設定は独自ファイルへ保存する。

## 段階0 技術検証の結果（2026-10-06、検証版 0.0.1〜0.0.3）
1. **パネルの正体**：本体標準パネルは、結合中は本体が1枚の画面に直接描画しており、独立した窓は無い。切り離すと、本体自身が描く独立窓（class `aviutl2Manager`、オーナー＝メイン窓）になる。他者製プラグインのパネルも同じ扱い。
2. **取り込み**：切り離し窓を子窓化して自前の窓へはめ込むことに成功。表示・大きさ追従・操作・再生・ショートカットキーはすべて正常。返却も可能。
3. **自動化**：本体のレイアウトファイル（`Default\*.layout`、`floating=1` で切り離し）を生成し、「表示→レイアウト→TP_GUIdocker」を名前で探して実行すれば、全パネルを一括で切り離し→取り込みできる。
   - 本体はプラグイン読込前にレイアウト一覧を作るため、初回だけ再起動が必要。本体の「アプリケーションを再起動」機能で解消できる見込み。
   - メニュー項目の番号はプラグイン数で変わるため、必ず名前で探す。
4. **右クリックメニュー**：本体は `TrackPopupMenu`（オーナー＝メイン窓）で表示。IAT 差し替えで横取りできる。「ウィンドウ配置」サブメニューに「ウィンドウを統合」「ウィンドウを閉じる」があり、項目番号は毎回変わるため文字列で判定する。
   - 「統合」を阻止できた。ここへ独自項目（分割・タブ化・最大化・元に戻す等）を差し込める。
5. **パネル移動**：色設定・シーンリスト等は、本体が描く見出し帯から `SC_MOVE` を発行し、取り込み後もコンテナ内で自由に動いてしまう。プレビュー等は Windows 標準のタイトルバーに依存するため、取り込み後は動かない。本番では `SC_MOVE` を阻止し、移動は自前のタブで行う。
6. **返却**：切り離し時の位置へ戻るため、配置はバラバラになる。本番では返却後に「戻り先レイアウト」（既定：basic）を本体に適用する。

## 段階1 の決定事項（2026-10-06）
- 入れ物の位置：AviUtl2 本体の窓の中全体。メニューバーと下端のフッター（`style.conf` の `FooterHeight`）の間を丸ごと自前の分割画面にする。
- 戻り先レイアウト：既定は「自由分割へ入る直前の本体配置」をプラグインが自動保存したもの（`TP_GUIdocker_元の配置.layout`）。設定で任意のレイアウト（例：ユーザー自作の basic）を指定可能。
  - 留意：basic はユーザー自作であり、本体標準には存在しない。前提にしてはならない。
- 起動時：前回終了時の状態を引き継ぐ（自由分割で終了→自動で自由分割）。

## 段階1 設計
- **データフォルダ**：`CONFIG_HANDLE::app_data_path` を使う（フォルダ探索は予備）。
- **入れ物**：メイン窓の子窓。メイン窓をサブクラス化し、`WM_SIZE` で追従。配色は `style.conf` の `[Color]`（Background, WindowSeparator, TitleHeader 等）に合わせる。
- **分割木**：節＝縦／横分割（比率）、葉＝パネル群（段階1は見出し帯＋クリックでの切替のみ、ドラッグは段階2）。
- **パネルの識別**：レイアウトファイルの節名（`preview` 等）と窓の題名（「プレビュー編集」等）の対応は、生成レイアウトで各パネルに固有の仮位置を与え、切り離し後の窓位置と照合して自動で学習する。
- **境界線**：葉の間の隙間をドラッグで比率変更。最小サイズを守る。
- **保存**：分割木・比率・対応表・状態を `TP_GUIdocker.ini`（プラグイン専用）へ。本体の `aviutl2.ini` には書き込まない。
- **初期配置（AE 風）**：左＝シーンリスト／エクスプローラー類、中央上＝プレビュー編集、右＝オブジェクト設定・色設定、下＝レイヤー編集。未割当の表示中パネルは右の群へ。
- **安全装置**
  - 取り込み失敗・パネル消失・例外を検知したら、全返却して戻り先レイアウトを適用。
  - 本体バージョンが検証済み一覧に無い場合は無効化して通知（設定で強制有効化可）。
  - 終了時は全返却＋戻り先レイアウト適用を行い、プラグインを外しても標準画面で起動できる状態を保つ。
- **パネルの勝手な移動防止**：取り込み中パネルの `SC_MOVE`・`SC_SIZE` を阻止。「ウィンドウを統合」は阻止（段階2で独自項目に置換）。
- **起動時の自動化**：`RegisterPlugin` で入れ物を作り、メッセージループ開始後に「TP_GUIdocker」レイアウトを適用して取り込む。メニューに無い（初回）場合は、本体の「アプリケーションを再起動」を案内する。
